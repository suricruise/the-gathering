# Known limitations and launch boundaries

- Public launch remains blocked until the [launch readiness gates](LAUNCH_READINESS.md) are closed. Local tests do not prove hosted configuration, provider quotas, physical microphone permissions, TURN/mobile-network connectivity or real alert delivery.
- Voice requires the always-on independent worker and healthy LiveKit. Token expiry alone does not forcibly end every existing malicious connection; worker monitoring/recovery is essential. The app does not record voice by default and cannot prevent participants from capturing audio externally.
- In-app notifications are implemented. Email/push infrastructure is deliberately disabled; actual Auth verification/recovery mail still requires configured Supabase SMTP. Reminders/cleanup require private scheduled jobs.
- Age eligibility uses private self-attestation. No identity verification/KYC or CAPTCHA client is implemented. The operator must evaluate abuse and age-assurance needs.
- Files are bounded and format-validated; images are sanitized WebP and clips inspected. There is no antivirus/sandbox scanning service. Non-image files download rather than execute inline. Evaluate general file access before an unrestricted launch.
- Private messages are not end-to-end encrypted. Report evidence and audit/backups have separate bounded/operator retention policies; account deletion does not instantly erase every backup. Account ownership must be transferred before deletion.
- Event banners are curated local designs. Ambiguous fall-back daylight-saving wall times use PostgreSQL's standard-time interpretation; nonexistent spring-forward times are rejected. Daily Scripture is an optional small curated public-domain KJV rotation, not a live editorial service.
- Some context/roster selectors remain bounded operational views (for example community member rosters and staff-recipient selection). Admin accounts/message/post/event histories have cursor pages; large-community roster UX and high-scale analytics need further capacity work. Usage metrics are database counts/admissions, not fabricated live-person analytics.
- General legal policies are drafts for review. No contracting entity, privacy contact, jurisdiction-specific rights or emergency/support service is invented by the app. Establish actual staffed support, appeal and incident procedures before inviting the public.
- Default framework/provider error logs and backups need restricted access and approved retention. Application structured monitoring intentionally excludes raw messages, request bodies, credentials and personal URLs. A hosted log drain/alert destination still needs operator configuration.

- The installable PWA is a web app, not an App Store/Google Play package or native desktop installer. Physical OS installation, Apple launch images and background voice still require on-device acceptance; push notifications are not enabled. See [PWA boundaries and checks](PWA.md).
